# Architecture Overview

This document summarizes the runtime and data flow of Overleaf Comment Exporter.

## Components

- Browser action popup (extension/src/popup.ts)
  - Starts extraction on the active Overleaf tab.
  - Receives extracted rows and writes CSV or XLSX.
- Content script (extension/src/content.ts)
  - Runs on Overleaf pages.
  - Expands comments, collects review entries, resolves highlights/context, and returns normalized rows.
- Shared types (extension/src/types.ts)
  - Defines export row schema used between popup and content script.

## High-Level Flow

1. User opens the extension popup and chooses CSV or XLSX export.
2. Popup sends an extract-comments message to the content script.
3. Content script:
   - Ensures review comments are expanded.
   - Builds editor text coverage from available sources.
   - Iterates visible and scroll-revealed review entries.
   - Resolves best available highlighted text and context around position.
   - Returns rows plus any non-fatal extraction errors.
4. Popup serializes returned rows to CSV or XLSX and triggers browser download.

## Data Boundaries and Privacy

- Processing occurs locally in the browser context.
- No network transmission of extracted comment content is performed by the extension.
- Persistence occurs only when the user downloads an export file.

## Reliability Strategy

Extraction uses layered fallbacks because Overleaf UI and editor state may vary:

- Prefer direct associations when available.
- Use anchored selectors and position heuristics when direct match is unavailable.
- Use context extraction around character position as a final readable fallback.

This strategy favors robust output generation over perfect highlight certainty in all edge cases.

## Packaging and Release

- TypeScript bundles are generated into extension/dist.
- AMO artifacts are generated by web-ext into extension/web-ext-artifacts.
- Release readiness is tracked in [AMO_RELEASE_CHECKLIST.md](AMO_RELEASE_CHECKLIST.md).
